# 数据模型说明

## 一条设计原则：国家标准进代码，园所数据进数据库

项目里有两类"数据"，刻意分开存放：

| 类型 | 存放位置 | 原因 |
|------|----------|------|
| 《3—6岁儿童学习与发展指南》的领域—子领域—目标结构 | `src/lib/domain.ts` | 国家文件规定的固定框架，需要类型系统约束和版本管理，不该由用户随意增删 |
| ECERS-3 的 6 个子量表 / 35 个条目 | `src/lib/ecers.ts` | 同上，且条目编号需要与官方手册严格对齐 |
| 教案、教研、观察、评分、幼儿名单… | `data/teaching-ecer.db` | 园所自己产生的数据 |

好处是：教案勾选的"目标"存的是 `science-1-2` 这样的稳定 ID，而不是一串中文文本——将来《指南》措辞调整，改一处代码，所有历史记录跟着更新。

## 领域模型（`src/lib/domain.ts`）

```
Domain（五大领域：健康/语言/社会/科学/艺术）
└── SubDomain（子领域，如「科学探究」「数学认知」）
    └── DomainGoal（目标，如「具有初步的探究能力」）
```

共 5 个领域、11 个子领域、30 条发展目标。`ALL_GOALS` / `GOAL_MAP` 提供扁平索引，供观察记录和教案按目标打标签、按目标反查。

另含几组业务枚举：`AGE_GROUPS`（托/小/中/大班）、`OBSERVATION_METHODS`（6 种观察方法）、`DAILY_SCENES`（一日生活环节）、`RESEARCH_TYPES`、`FAMILY_NOTE_KINDS`、`RESOURCE_CATEGORIES`。

## ECERS 模型（`src/lib/ecers.ts`）

6 个子量表、35 个条目：

| 子量表 | 条目号 | 数量 |
|--------|--------|------|
| 空间和设施 Space and Furnishings | 1–7 | 7 |
| 个人日常照料 Personal Care Routines | 8–11 | 4 |
| 语言和读写 Language and Literacy | 12–16 | 5 |
| 学习活动 Learning Activities | 17–27 | 11 |
| 互动 Interaction | 28–32 | 5 |
| 活动组织 Program Structure | 33–35 | 3 |

计分函数遵循 ECERS 规则：

- `subscaleAverage()` —— 子量表均分，**NA 条目不计入分母**；整个子量表全 NA 返回 `null`
- `totalAverage()` —— 总均分是**所有已评条目的算术平均**，不是子量表均分再平均（这是常见误算点）
- `qualityLevel()` —— <3 不适宜 / <5 最低限度 / <6 良好 / ≥6 优秀

## 数据表（`src/lib/schema.sql`）

```
classes ──┬── children ──┬── observations
          │              ├── family_notes
          │              └──（删除幼儿时 CASCADE 一并清除其个人记录）
          ├── ecers_assessments ── ecers_scores（35 行/份，CASCADE）
          └── class_reviews

research_sessions ── class_reviews
lessons ──────────── class_reviews（听评课可关联到具体教案）
resources（独立）
```

### 外键删除策略（刻意区分）

- `children → observations / family_notes`：**CASCADE**。删除幼儿时连带删除其观察记录与家园沟通记录——个人信息应当一并清除。
- `classes → children`：**SET NULL**。删除班级不删幼儿，幼儿变为"未分班"，避免误删班级导致名单丢失。
- `ecers_assessments → ecers_scores`：**CASCADE**。评分是评估的一部分，不能独立存在。
- `research_sessions / lessons → class_reviews`：**SET NULL**。听评课记录本身有独立价值，教案被删不该带走评课意见。

### JSON 列

SQLite 没有数组类型，`goal_ids` 和 `tags` 统一存 JSON 文本，通过 `src/lib/db.ts` 的 `parseJsonArray()` / `toJsonArray()` 读写。数据量小，没有按数组元素检索的性能需求，不值得为此拆关联表。

## 数据访问层（`src/lib/db.ts`）

`node:sqlite` 的 `DatabaseSync` 是同步 API，对当前数据规模完全够用，省掉了连接池。有两个要点：

1. **单例连接**用 `globalThis` 缓存 —— Next.js 开发模式下模块会被反复求值，否则会泄漏文件句柄。
2. **行对象要转普通对象** —— `node:sqlite` 返回的是 **null 原型对象**，React Server Components 拒绝把它们序列化给客户端组件（报 `Only plain objects... can be passed to Client Components`）。`all()` / `one()` 在返回前统一 `{...row}` 转换，调用点就不用各自记得处理。
