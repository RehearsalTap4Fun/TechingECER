# 学前教育教研平台 · TeachingECER

面向幼儿园的教研工作台：把**教案设计、教研管理、儿童观察、环境评估、家园共育**收拢到一个本地应用里，所有数据留在园所自己的机器上。

**ECER** 在本项目中有两层含义：
- **E**arly **C**hildhood **E**ducation & **R**esearch —— 学前教育教研，项目主体
- **ECERS-3** —— 幼儿学习环境评量表（第三版），作为其中的环境评估模块

## 功能模块

| 模块 | 路径 | 解决什么 |
|------|------|----------|
| 教研工作台 | `/` | 各模块数量概览、五大领域教案分布、最近动态 |
| 教案与活动设计 | `/lessons` | 按《3—6岁儿童学习与发展指南》五大领域组织活动设计，可关联到具体发展目标，支持按领域/年龄班/关键词检索 |
| 教研管理 | `/research` | **专题 → 月度主题模块 → 教研活动 → 课例实践**四层结构，进度与预期成果自动对账 |
| 儿童观察记录 | `/observations` | 客观记录 → 分析解读 → 支持策略三段式，支持 6 种观察方法，可跨领域关联《指南》目标 |
| ECERS-3 环境评估 | `/assessments` | 6 个子量表 35 个条目 1~7 分制打分，自动计算子量表均分与总均分，NA 条目按规则排除 |
| 家园共育 | `/family` | 家访、家长面谈、日常沟通、成长反馈的统一台账 |
| 资源库 | `/resources` | 索引绑定的资料目录，**按正文内容自动分类**并分待归档/已归档，支持全文检索 |
| 班级与幼儿 | `/classes` | 班级与幼儿名单，观察记录和家园沟通都挂在幼儿名下 |

## 教研以「专题」为主线

园所的教研不是一次次孤立的活动，而是一条学期/学年的主线：一个专题下分几个月度主题模块，每月一次大教研，再落到课例实践。系统按这个结构组织：

```
专题 / 小课题 / 教师培养计划
├── 教研背景（要解决的真问题）· 理论支撑
├── 教研目标 —— 认识 / 能力 / 实践 / 成果 四类
├── 月度主题模块（主题一、二、三…）
│   └── 教研活动（真问题 → 研讨记录 → 结论共识 → 后续行动）
│       └── 课例实践（听评课记录）
└── 预期成果 —— 认识性 / 物化 / 操作性，可逐条勾选对账
```

这套结构直接照着园所实际的教研计划文档建模——背景、四类目标、月度主题、三类预期成果，是这类文件的通用骨架。

**已有计划文档的话不用重新录入**：把计划放进资料目录，到「教研管理 → 从计划文档导入」，
系统会解析出背景、理论支撑、四类目标、主题模块与三类预期成果，填进表单供你核对，确认后才入库。
解析不到的部分会明确标出「需手填」，不会悄悄留空。已导入过的文档会标记为「已建专题」，不会重复导入。

```bash
npm run parse -- 某份教研计划.docx   # 命令行试跑解析，调规则时用
```

**为什么值得这样组织：**

- 打开任何一次教研活动，页面上就显示它所属专题的目标——写研讨记录时对照着看，避免开成漫谈。
- 专题页实时显示进度：主题模块开展了几个、累计多少场教研、多少次课例实践、预期成果达成几项。学期末不用再翻记录凑材料。
- 不强制归属：临时的单次教研可以不挂专题，会显示在「未归属专题」里。

## 资料目录：绑定一次，之后放文件就行

这是一个**本地工具**，首次使用时绑定一个你自己的文件夹作为资料目录——**把文件夹拖进绑定区即可**，系统会在本机自动找到它的完整路径（也可以直接填路径）。之后：

1. 把文档直接放进那个文件夹（访达、资源管理器里拖进去即可，不用打开网页上传）
2. 进入「资源库」页面时自动索引，新文件和改动过的文件会被重新解析
3. 系统按**正文内容**给出分类、领域、年龄班建议，连同判定依据一起展示
4. 你确认或改判后**归档**，该资料随即出现在对应模块的「相关资料」中
5. 没归档的停在「待归档」队列里等着处理

**文件始终留在你的目录里**——应用不复制、不改名、不移动，只在数据库里记位置、指纹和提取出的正文。删掉文件就是删掉；改了文件下次进页面会重新解析。

归档后各模块能看到的资料：

| 模块 | 显示的分类 |
|------|-----------|
| 教案与活动 | 课程方案、绘本书单、音乐律动 |
| 教研管理 | 培训资料、政策文件 |
| 家园共育 | 家长材料 |
| ECERS 评估 | 政策文件 |

### 绑定目录的两种方式

**拖进来**（推荐，仅本机可用）：把文件夹从访达/资源管理器拖到绑定区，或点击选择。

浏览器出于安全考虑**不会**把文件夹的真实路径交给网页——这是所有浏览器的限制。所以做法是：浏览器交出文件夹名和内部若干文件的相对路径与大小，服务端拿着这些信息在本机的桌面、文稿、下载等常用位置反查同名目录，再用文件大小确认是哪一个。桌面和文稿下有两个同名文件夹时能准确区分；找不到或对不上就明确提示手填，不会瞎猜。

**直接填路径**：
- macOS —— 访达里选中文件夹，按 <kbd>⌥⌘C</kbd> 拷贝路径
- Windows —— 资源管理器里按住 <kbd>Shift</kbd> 右键文件夹 →「复制为路径」

### 应用内创建的内容也会写一份到资料目录

在应用里新建的教案、教研专题、教研活动（含听评课）、观察记录、家园沟通、ECERS 评估，保存时会**同时导出一份 Markdown** 到资料目录的 `应用导出/` 子目录：

```
<资料目录>/应用导出/
├── 教案/0001-有趣的影子.md
├── 教研/专题/0001-促进学前儿童前阅读核心经验获得的教学实践研究.md
├── 教研/活动/0002-前阅读核心经验的内涵辨析.md
├── 观察记录/0003-示例·小满 2026-09-17.md
├── 家园共育/…
└── ECERS评估/…
```

这样在访达里就能直接看到、发给同事、随你原有的备份方式一起备份。

**这是单向导出——应用是唯一的写入方。** 直接编辑导出文件不会回流到应用，下次在应用里保存会覆盖它（每个文件顶部都写明了）。改标题会重命名文件并删掉旧的；删除记录会删掉对应文件。`应用导出/` 被扫描器跳过，不会被当成新资料索引回待归档队列。

绑定目录时会自动全量导出一次；「重新导出应用内容」按钮可随时补齐或修复。

> 观察记录与家园沟通含幼儿姓名，导出文件与资料目录里的其他文档同等敏感，注意目录本身的存放位置与共享范围。

### 文件状态

- **待归档** —— 已索引，系统给了分类建议，等人确认
- **已归档** —— 分类经人确认，出现在对应模块
- **已失联** —— 文件已不在目录里（删除/改名/移走）。索引记录**保留**而不是直接删除，以免只是临时移动就丢掉已做的分类；文件放回原处会自动恢复。确认不要了可以手动清理。

### 自动分类

读取**正文内容**（不是只看文件名）判定分类、领域、年龄班与标签，判定依据（命中了哪些词、置信度多少）一并展示，置信度低于 50% 的高亮提示优先复核。

分类用的是**本地词表打分，不调用任何外部模型**。园所文档常含幼儿姓名和内部管理信息，不应离开本机；学前教育的文本用词高度专门化（前阅读、图画书、律动、环创…），词表法在这个领域已经足够准。词表在 `src/lib/classify.ts`，可按园所习惯增补。

提取出的正文同时进入全文检索：搜"撕贴"能直接找到正文里写了撕贴的那份教案，并显示命中片段。

### 点开一份资料会怎样

**在运行本应用的那台机器上**（浏览器地址是 `localhost`）：

- 点标题 → **在访达 / 资源管理器里定位到这份文件**（文件夹打开、文件选中）
- 点「打开」 → 用系统默认程序打开（Word 文档直接进 Word）
- 点「下载」 → 走浏览器下载

**从园所内网的其他机器访问时**，定位功能自动关闭——那样打开的是*服务器*那台机器的窗口，对面前的人毫无意义。此时点标题退回浏览器行为：PDF / 文本 / 图片直接预览，Word / PPT / Excel 下载。

文件已从目录里删除时，定位会提示「文件已不在资料目录里」。

判断依据是请求的 Host 头：`localhost` / `127.0.0.1` 视为本机。这个判断偏保守——同机但用局域网 IP 访问也会被当成远程，结果只是退回下载，绝不会误在服务器上弹窗。

```bash
npm run classify -- 某个文件.docx   # 单个文件的分类试跑，调词表时用
npm run classify:eval               # 分类器回归评测（改词表后必跑）
npm run parse -- 某份教研计划.docx  # 计划解析试跑
```

词表是人工维护的，改动一处很容易顾此失彼，所以 `fixtures/classify/` 下放了一组带标注的样例。**「应当判为未判定」和「判对」同等重要**：政策文件不该被塞进某个领域，覆盖全园的文件不该被塞进某个年龄班——给出一个自信的错误答案比留空更糟。

## 技术选型

- **Next.js 16**（App Router / Server Actions）+ **React 19** + **TypeScript**
- **Tailwind CSS v4**
- **Node.js 内置 `node:sqlite`** —— 零原生依赖，不需要编译 `better-sqlite3`，也不需要额外的数据库服务
- **fflate**（解 OOXML 压缩包）+ **pdfjs-dist**（PDF 取文本）—— 均为纯 JS，不引入原生二进制

选 SQLite 而不是 MySQL/Postgres 是刻意的：一所幼儿园的数据量（几千条记录）单文件数据库绰绰有余，园所不需要运维数据库，整个系统拷贝一个目录就能搬走或备份。

## 快速开始

```bash
npm install
npm run db:init     # 建表 + 写入示例数据
npm run dev         # http://localhost:3100
```

生产运行：

```bash
npm run build
npm run start
```

其它命令：

```bash
npm run typecheck   # TypeScript 检查
npm run db:reset    # 删库重建（会清空所有数据）
npm run import      # 批量导入目录下的文档并自动分类
npm run classify    # 单个文件的分类试跑
```

## 数据与隐私

- 所有数据保存在 **`data/teaching-ecer.db`**（单个 SQLite 文件），不上传任何外部服务。
- `data/*.db` 已写入 `.gitignore`：**幼儿姓名、出生日期、监护人联系方式等个人信息不会被提交到代码仓库**。
- 文档留在**你自己绑定的资料目录**里，应用只索引不复制；提取的正文存在数据库中。
- 应用内创建的内容存在数据库里，同时导出一份 Markdown 到资料目录的 `应用导出/`。
- 备份 = 拷贝 `data/`（数据库）**和你的资料目录**两处。

> ⚠ 数据库是 WAL 模式，`data/` 下有 `teaching-ecer.db`、`-wal`、`-shm` 三个文件，**必须一起拷**。
> 只拷 `.db` 会丢掉尚未合并进主库的最新写入——这是真踩过的坑。
> 最稳妥的做法是先停掉服务再拷，或者整个 `data/` 目录一起拷。
- 如需在园所内网多人共用，在一台机器上 `npm run start`，其他人访问该机 IP 的 3100 端口即可。当前版本**没有登录与权限控制**，只适合可信内网使用。

## ⚠️ ECERS-3 版权说明

本项目只收录 ECERS-3 的**子量表与条目编号、名称**，用于组织评分结果和生成报告。

各条目 1/3/5/7 分下的**具体评分指标、观察说明与计分规则原文受版权保护，未包含在本仓库中**。实际评分时请对照正式出版的《幼儿学习环境评量表（第三版）》手册，由受过训练的评估者观察后评定。请勿将手册原文录入本仓库。
